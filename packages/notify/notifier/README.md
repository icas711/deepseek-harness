# `@deepseek-ai/dsh-notifier`

Service Definition возможности уведомлений: сервис `ctx.notifier` доставляет человеку уведомления, адресованные логину, и владеет биндингами «логин → пункт доставки» и одноразовыми кодами сопряжения. Определение не знает ни Telegram, ни чатов: провайдер ([`dsh-telegram-notifier`](../telegram/README.md)) владеет транспортом, формулировками и способом, которым пользователь предъявляет код.

## Сервис `ctx.notifier`

| Метод | Контракт |
|---|---|
| `send({ login, kind, title, sessionId })` | Доставляет уведомление в пункт доставки, привязанный к `login`. Незавёршенный (unbound) логин молча пропускает запрос (`unbound`) — доставлять некуда; неудача доставки отклоняется исключением, чтобы звонящий отличал пропуск от сбоя и мог повторить. `kind` — закрытый набор `paused`/`interrupted`/`waiting-station`/`resumed`/`completed`/`failed`; формулировки — забота провайдера. |
| `beginBinding(login)` | Выдаёт одноразовый код сопряжения (`{ code }`) с ограниченным сроком жизни (`bindingCodeTtlMs`). Пользователь предъявляет код провайдеру; новый запрос кода для того же логина отменяет прежний. Коды живут только в памяти процесса: рестарт обнуляет их, пользователь запрашивает новый. |

Провайдер реализует доставку (`deliver`) и, приняв код от пользователя, вызывает защищённый `completeBinding(code, chatId)` базового класса: код проверяется по таблице ожидающих, привязка коммитится в документ.

## Документ биндингов

Документ `telegram-bindings.json` (путь — обязательное поле конфига `bindingsPath`; композиция передаёт `dshHomePath('telegram-bindings.json')`) хранит записи `{ login, chatId, boundAt }`, где `chatId` — брендированный непрозрачный идентификатор пункта доставки. Каждая привязка перечитывает документ под writer-lock из `dsh-atomic-write`, сливает записи по `login` (повторная привязка перезаписывает) и коммитит весь документ одной атомарной заменой с правами `0600` (каталог `0700`): два процесса с общей домашней папкой не затирают биндинги друг друга. Битый документ роняет загрузку сервиса громко, с подсказкой оператору. Записи не удаляются: отвязки на этом этапе нет.

## Model Experience

None, as `notifier` is notification plumbing: nothing it owns enters a model request, and the texts it delivers travel to a human's chat, not to the model.

#### KV Cache effect

No direct effect: the package adds no prompt sections, no tools, and no logged input.

## Known Limitations and Deferred Work

- **UI-страница привязки и RPC — следующий этап** — `beginBinding` пока доступен только как API сервиса: страницы «Уведомления» и RPC-эндпоинтов нет, поэтому в композиции по умолчанию коды никто не выдаёт.
- **Отвязки нет** — записи документа не удаляются; повторная привязка логина перезаписывает `chatId`, но отвязать логин (перестать слать) нельзя.
- **Коды переживают только процесс** — таблица ожидающих кодов в памяти: рестарт сервера обнуляет выданные коды до истечения срока.
