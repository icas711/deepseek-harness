# dsh-client-ui-tasks

Страница «Задачи» веб-интерфейса: список СВОИХ задач супервизора, возобновление стоящих и раздел «Уведомления» о привязке Telegram.

## Поверхности

- **Страница «Задачи»** (слот `shell.overlay`): статус бейджем (running / paused / interrupted / waiting-station / completed / failed), станция исполнения, время последнего изменения, кнопка «Продолжить» для стоящих задач (interrupted / paused / waiting-station) и переход к сессии. Отметки «завершённой» нет: исход работы фиксирует только хост (исход turn'а в проводке шлюза).
- **Кнопка «Задачи»** в боковой панели (слот `sidebar.footer.action`): широкое состояние — иконка с подписью, рейка — иконка.
- **Deep-link'и**: `/tasks` открывает страницу после загрузки; `/session/<id>` открывает сессию, когда список сессий готов. Адрес вычищается заменой.
- **Раздел «Уведомления»** в настройках (`settings.section`, порядок 40): статус привязки логина к Telegram и одноразовый код через `notifier.beginBinding`; подтверждение делает пользователь командой боту.

## Данные

Хост остаётся единственным источником факта: список читается через `tasks.list` (изоляция на хосте — только задачи вызывающего, админ видит только свои), возобновление — `tasks.resume` с перечитыванием. Неудача возобновления показывается текстом хоста.

## Model Experience

Поверхность ничего не пишет в модель: задачи и статусы — серверные факты. Модель узнаёт о работе из обычных сообщений сессии; страница только читает реестр супервизора.
