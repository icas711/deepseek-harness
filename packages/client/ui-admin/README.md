# dsh-client-ui-admin

Страница «Администрирование» в настройках браузера: пользователи входа по паролю, их роли и устройства — всё через домен `admin.*` шлюза ([`dsh-host-apiproxy`](../../host/apiproxy/README.md)), который на каждом методе данных проверяет роль `admin` вызвавшего. Регистрация секции (`settings.section` с id `admin`, после «Пресетов агента») условная: плагин опрашивает `admin.status` (доступен любому аутентифицированному) и ставит секцию только админу; перелогин (`connection/reset`) перепроверяет и ставит/снимает секцию заново, отказ пробы читается как «не админ». Клиентская проверка — удобство сокрытия, подлинный гейт на хосте.

Страница: список пользователей (логин, роль, момент создания, действия), форма создания (логин + пароль с генератором + роль), сброс пароля (клиент генерирует новый, хост хранит только scrypt-хэш; все устройства логина отключаются, новый пароль показывается в диалоге один раз), удаление с подтверждением, переключение роли и устройства: разворачиваемый список живых сессий с отзывом по одному и «отозвать все». После каждой мутации список перечитывается. Словарь — единственный, русский (`settings.admin`).

## Model Experience

None; чисто браузерная поверхность над существующим wire-контрактом.

#### KV Cache effect

None; в промпт не попадает.
