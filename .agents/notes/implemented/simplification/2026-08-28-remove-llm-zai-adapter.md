# Agent Note: Удаление захардкоженного Z.ai LLM-адаптера (llm-zai)

Status: implemented

## Problem

Страница «Настройки → Модели» веб-GUI показывает карточку «Z.ai» (маршрут `zai-official`) при каждом запуске: плагин `@deepseek-ai/dsh-llm-zai` смонтирован в базовом бандле (`packages/bundle/base/cordis.patch.yml`) безусловно, и при монтировании регистрирует себя в каталоге настраиваемых провайдеров (`ctx.llm.registerConfigurableProviders`). Без ключа маршрут числится «дремлющим»: карточка присутствует на странице, но непригодна для запросов. Форк развивается для русскоязычных пользователей и не ведёт GLM-чат через собственный адаптер; карточка — мёртвый интерфейс, который дефолтная композиция навязывает каждому развёртыванию, а отказ требует персонального оверлея с `disabled`.

## Decision

Пакет `packages/llm/llm-zai` удалён целиком: вместе с монтированием в `packages/bundle/base/cordis.patch.yml`, зависимостью в `packages/bundle/base/package.json`, ссылкой в `tsconfig.host.json`, гайдом `docs/llm-zai-setup.*` и записями в `pnpm-lock.yaml`. Веб-поиск Z.ai сохранён без изменений: `web-search-zai` остаётся смонтированным, `searchProvider: zai` — дефолтным маршрутом поиска, а ключ `ZAI_API_KEY` разрешается на каждый поиск из окружения запуска или хранилища учётных данных; страница «Модели» больше не управляет Z.ai-ключом чата, и комментарий к веб-поиску в `cordis.patch.yml` это фиксирует. GLM остаётся доступен для чата через маршруты `zai` и `zai-coding-cn` из каталога pi-ai (`packages/llm/llm-pi-ai`), которые по-прежнему видны в списке провайдеров страницы «Модели».

## Alternatives considered

**Скрыть карточку только в UI фильтром каталога.** Проигрывает: мёртвый плагин остаётся смонтированным, фильтр — точечный хак в Consumer против общего каталога провайдеров, а пакет и его тесты продолжают существовать без потребителя.

**Отключать запись оверлеем (`disabled: true`) в каждом профиле.** Проигрывает: каждый профиль форка таскает оверлей против базовой композиции, а базовый бандл продолжает собирать и поставлять неиспользуемый адаптер.

**Удалить заодно `web-search-zai` и дефолтный поиск `zai`.** Отклонено владельцем форка: веб-поиск Z.ai остаётся маршрутом поиска по умолчанию.

**Отфильтровать опции `zai`/`zai-coding-cn` из каталога pi-ai.** Отклонено: содержимое каталога принадлежит зависимости pi-ai, а фильтр скрыл бы рабочий маршрут GLM-чата, который остаётся намеренно доступным.

## Consequences

Страница «Модели» больше не предлагает маршрут `zai-official`; опции `zai` и `zai-coding-cn` остаются. Сохранённая секция настроек `llm-zai:` (если она была) становится мёртвой: редактирующего её адаптера нет, страница её не показывает. Квота-пауза (`packages/guard/quota-pause`) не привязана к адаптеру — механизм общий; заметка [2026-08-16-quota-pause](../feature/2026-08-16-quota-pause-and-live-telemetry-mode.md) обновлена под текущую маршрутизацию, как и [2026-08-24-web-search-zai-provider](../feature/2026-08-24-web-search-zai-provider.md). Той же правкой в корневом `AGENTS.md` зафиксирована языковая политика форка: новая документация только на русском.

## Verification

- `pnpm install` — `pnpm-lock.yaml` без записей `llm-zai`.
- `pnpm run typecheck` — зелёный; `pnpm exec vitest run packages/llm` — 675 тестов зелёные; `pnpm run verify-cordis-config` не имеет претензий к `bundle/base`.
- Поиск по репозиторию: упоминания `llm-zai`/`zai-official` остаются только в исторических записях (разделы Problem действующих заметок и эта заметка).
