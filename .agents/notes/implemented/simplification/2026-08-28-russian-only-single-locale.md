# Agent Note: Одноязычный русский форк — локали и документация

Status: implemented

## Problem

Форк развивается для русскоязычных пользователей, но нёс две многоязычные нагрузки. Веб-клиент вёз реестр трёх локалей (zh — источник ключей и фолбэк, en, ru) с переключателем языка в настройках, хранимой настройкой `locale.preference`, определением языка браузера и событием `locale/change`; локальная feature-заметка добавляла ru как равноправный язык многоязычного продукта (консолидирована ниже). Документация обслуживалась двуязычными парами — английский `foo.md`, китайский `foo.zh.md` и запись согласованности `foo.i18n.yaml` — с гейтом парности, merge-драйвером, подсистемой перевода `docs/i18n/`, скиллом `dsh-translate-docs` и двухлокальным сайтом. При этом русских версий документов не существовало вовсе: базовые страницы были английскими, а китайские — необслуживаемым переводным корпусом, который форк не читает.

## Decision

Продукт и документация форка одноязычные: русский интерфейс, одноязычные доки.

**Клиент.** `@deepseek-ai/dsh-client-locale` — реестр словарей без выбора языка: `register(ns, dict)` с типизированной проверкой против union ключей namespace, `bind(ns)`, снапшот `{revision}` для HMR-обновления. Общий словарь `common` — русский и источник ключей. Удалены: строка Language в настройках, секция настроек `locale` с полем `preference`, определение языка браузера, событие `locale/change`, константа `FALLBACK_LOCALE`. Механизмы отображения копии не изменились: стандартный сид `t`, label-thunks, copy-props атомов ui-primitives и непереводимая граница (строки ошибок — английские, дизайн-литералы — вне словарей) остаются в собственности [заметки о полном развороте копии на локальный сид](../architecture/2026-07-30-client-locale-full-rollout.md).

**Документация.** Все пары снесены: 2176 файлов `.zh.md`/`.i18n.yaml`, каталог `docs/i18n/`, скилл `dsh-translate-docs`, скрипты перевода и парности, merge-драйвер `dsh-translation-pairing`, гейты translation-pairing/translation-prompt, вторая локаль сайта. Базовые английские `docs/` остаются рабочим корпусом; новые и изменяемые страницы и README — только на русском (политика в корневом `AGENTS.md`). Сайт `website/` проецирует один локал с английским содержимым.

**Заметки.** Шесть заметок о двуязычной машинерии заархивированы как замороженная история (bilingual-docs-and-pairing-gate, translation-prompt-v4-contract, briefed-minimal-translation-updates, automatic-translation-pairing-merges, lightweight-routine-documentation-translation, chinese-contract-terminology). Две локалевые feature-заметки (web-russian-locale, browser-derived-initial-locale) консолидированы в эту: их уникальные обоснования и отклонённые альтернативы сохранены ниже.

## Alternatives considered

**Оставить механизм переключения с единственным языком.** Проигрывает: настройки показывали бы выпадающий список из одного пункта, а `preference`, браузерная детекция и `locale/change` остались бы кодом без потребителя.

**Сначала перевести базовые доки на русский, затем удалять пары.** Отклонено владельцем форка: это отдельная большая переводческая работа; одноязычность инфраструктуры достигается удалением и не должна блокироваться переводом.

**Удалить документацию целиком (docs/, сайт, заметки).** Отклонено: документацию читают люди и агенты, на неё опираются AGENTS-инструкции и гейты качества; снесена только двуязычная надстройка, а не корпус.

**Заменить zh/en русским — пересмотр решения заметки о третьей локали.** Та заметка отклоняла русскоязычную замену, потому что трёхсловарный канон давал compile-time гарантию полноты на пакет, а продукт был многоязычным. Для одноязычного форка оба основания отпали: аудит полноты теперь проверяет единственный словарь против его же типизации ключей, и «третья локаль надстройкой» не соответствует аудитории.

**Множественное число через ICU или категории `.few`/`.many`.** Не вводилось (унаследовано от консолидированной заметки): ru-строки с числами используют родительный падеж в `.other` («2 фоновых задач» — точно для 5+, приближённо для 2–4); формы на ключах ломают изоморфизм ключей между словарями, если локалей снова станет несколько.

## Consequences

Потеряно: переключение языка на лету, en/zh интерфейсы, хранимая настройка `locale.preference` (секция `locale` в существующих `settings.yaml` становится мёртвой — схемы и читателя у неё больше нет), браузерная детекция, двуязычные README и пары документов, переводные гейты и merge-драйвер.

Сохранено: русские строки словарей байт-в-байт; compile-проверка полноты словаря; сид `t` и типизированные namespace; label-thunks и copy-props атомов; непереводимая граница; e2e-фикстуры пинированы на русском копии продукта.

Возврат многоязычности возможен известной формой: вернуть union `LocaleId`, словари по локали, активную локаль и настройку preference — контракт типизированного `register` сам перечислит каждый недостающий словарь ошибкой компиляции; возврат двуязычных доков — восстановление пар и гейтов из истории git.

## Testing

- `pnpm exec tsc -b tsconfig.client.json` — без ошибок; `pnpm run test:gui` — зелёный.
- `DSH_SNAPSHOT=replay pnpm run test:web` — воспроизведение без ключа; фикстуры ожидаемого вывода обновлены под русскую копию.
- `pnpm run website:build` — одноязычная сборка без мёртвых ссылок; обновлённый `doc-sync` — зелёный.
- `git grep` по живому коду и документации не находит `.zh.md`, `i18n.yaml`, `translation-pairing`, `dsh-translate-docs`.
