# Agent Note: Панель лимитов флота в настройках Web GUI

Status: implemented

## Problem

Лимиты worktree-фанлаута (`maxMembers`, `maxFanoutDepth`) настраивались только через `cordis.yml` композиции: с телефона или браузера — целевого сценария форка — их нельзя ни увидеть, ни изменить без SSH на сервер и перезапуска. Референс Orca решает это панелью «Agent Orchestration» в настройках (установка скилла + единственное числовое поле `nestedWorkerMaxDepth` + примеры промптов).

## Decision

Лимиты переезжают в settings-секцию `fleet`, не покидая существующие механизмы; нового RPC не появляется.

- **Служба флота** регистрирует пространство имён `fleet` при смонтированном settings-провайдере (`ctx.inject(['settings'])` в конструкторе): схема — та же `Fleet.Config`, composition-конфиг — базовый слой (`base`), `validate` — общая с конструктором проверка целочисленности. Значения читаются перед каждым `fanout()`, поэтому запись применяется к следующим фанлаутам без перезапуска; отсоединение провайдера возвращает composition-конфиг (паттерн `session-telemetry-otel`).
- **Провод**: секция открывается адресной записью `'fleet'` в allowlist `WEB_SETTINGS_NAMESPACES` apiproxy — по конвенции решение о web-видимости принимает apiproxy, а не регистрирующий плагин. Чтение и запись идут существующими `settings.describe` / `settings.update` (`expectedRevision` из прочитанного view).
- **Клиент**: пакет `dsh-client-ui-fleet-settings` (dual-face, node-половина пустая) регистрирует строку «Флот» в разделе «Общие» через `slots.inject('settings.general.item')` — многослотовую дыру настроек. Два целочисленных поля и «Применить»; ответ `settings.update` — следующая правда строки (включая отказ с его сообщением), внешняя правка (`settings/document-updated`) или пересоединение перечитывают view и заменяют неотправленный черновик.

## Alternatives considered

**Выделенный RPC `host.fleetLimits` по образцу `host.telemetryStatus`.** Отвергнуто: телеметрии RPC нужен, потому что её disclosure вычисляется бэкендом (changeable, sharing), а лимиты — готовая settings-секция; собственный RPC дублировал бы слой описания/обновления, который уже обслуживает конфликт ревизий и redaction.

**Отдельная секция настроек «Флот» вместо строки в «Общих».** Панель Orca несёт ещё установку скилла и примеры промптов; в dsh композиция монтирует инструменты всегда, примеры не нужны, а двухполевой редактор — размер строки. Секция добавила бы навигацию без новой информации.

**Прямое редактирование `cordis.yml` с host.** Нет горячего применения вне модели настроек и нарушает разделение слоёв композиции и пользовательских данных.

## Consequences

- Правки идут только парой полей одним `update`; отдельная кнопка сброса к базовым значениям (`replace({})`) отложена — база видна в открытом на host документе настроек.
- Изменение лимитов действует на следующие фанлауты; уже стартовавшие попытки не прерываются и не пересчитываются.
- Пустая/нецелая правка отказывается локально в строке, недопустимая пара — валидатором секции на host (`settings-rejected` с сообщением флота).

## Testing

- `packages/fleet/fleet/tests/fleet-settings.spec.ts`: entry-лимиты до записи, живое применение `maxMembers`/`maxFanoutDepth` к следующему `fanout()`, отказ недопустимой записи, откат к entry при отсоединении провайдера.
- `packages/host/apiproxy/tests/api-proxy-config.spec.ts`: секция `fleet` в описанном списке web-настроек.
- `packages/client/ui-fleet-settings/tests/`: контроллер (чтение view, запись с ревизией, отказы, гонки поколений, утилизация) и строка (поля, «Применить», отказ нецелого, недоступность без службы, слежение за внешней правкой).
- E2E-снапшот диалога настроек (`apps/web/tests/settings-chrome`) фиксирует собранную строку «Флот» со значениями по умолчанию.
