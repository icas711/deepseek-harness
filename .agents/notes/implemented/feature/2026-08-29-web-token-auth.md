# Agent Note: Токен-авторизация веб-поверхности

Status: implemented

## Problem

Веб-GUI управляет агентом с shell-доступом к машине, но его единственным контролем доступа была Host-fence в `client-connection` — защита от DNS-rebinding, а не от сознательного подключения: любой, кто мог достучаться до порта, управлял агентом. CLI намеренно запрещает `--host 0.0.0.0`, однако уровень композиции (patch-оверлеи, пользовательский слой) бинд на все интерфейсы разрешал — без какой-либо аутентификации. README `dsh-host-webserver` прямо называл auth вне скоупа.

## Decision

`dsh-host-webserver` получил `token` в `Config`: необязательный общий секрет, включающий гейт перед каждым HTTP-запросом и upgrade'ом — до матчинга маршрутов и fallback, обойти его через другой маршрут нельзя. Учётные данные принимаются в трёх каналах: сессионная cookie `dsh_web_token` (выдаётся с `HttpOnly; SameSite=Lax; Path=/` после первого предъявления), `Authorization: Bearer` (схема регистронезависима по RFC 9110), параметр `?token=` на любом пути — браузерный флоу работает без изменений фронтенда: первое открытие страницы по URL с `?token=` обменивает его на cookie, дальше все fetch и WebSocket несут cookie. Сравнение идёт по SHA-256-дайджестам через `timingSafeEqual` — равная длина гарантирована и не утекает ни длина секрета, ни его содержимое. Отказ — 401 `unauthorized` (для upgrade — полный 401-ответ и закрытие сокета). Пустой токен отвергается валидацией конфига: пустой секрет — это выключенный гейт, а не настроенный.

Включение — явное: флаг `--token` провайдера `web-startup` (пустое значение — usage-ошибка), строка `webserver` патча читает `ctx.webStartup.token`, а развёртывание может подставить своё выражение (например, `process.env.DSH_WEB_TOKEN`) в оверлее. URL-строка печатает `/?token=<encoded>` и для loopback, и для LAN-адреса, чтобы первый клик открывал GUI; при этом prompt-секция `app:web-surface` и переменная `DSH_WEB_URL` остаются без токена — model-visible ⟺ logged запрещает попадание секрета в логи сессии. Полномочия методов не ослаблены: токен открывает транспорт, но loopback-pinned RPC и trusted-host fence в `client-connection` продолжают работать как раньше.

## Alternatives considered

**Автогенерация токена при бинде `0.0.0.0`.** Отклонено: спрятанная политика в transport-пакете, который «не знает harness-концепций»; явный флаг или конфиг развёртывания честнее и не мешает будущему авто-режиму сверху.

**Гейт внутри `client-connection` (расширение `isTrustedApiRequest`).** Отклонено: оно закрывает только `/api`-маршруты и upgrade'ы реестра, статика и fallback-владелец остались бы открытыми; единая точка перед всем диспетчемом — webserver.

**Basic auth или реверс-прокси перед сервером.** Отклонено: контроль вне продукта не проверяется гейтами репозитория и не работает для WebSocket-даунлинков без дублирующей настройки.

**Заодно снять CLI-запрет `--host 0.0.0.0`.** Отклонено в этом изменении: это отдельное решение о публичном контракте флага; текущий запуск LAN-развёртывания идёт через оверлей и не требует его.

**Только Bearer, без cookie и query.** Отклонено: браузерный флоу без правок фронтенда недостижим — страницу нельзя открыть с заголовком.

## Consequences

Приобретено: LAN-развёртывание GUI с разделяемым секретом; у README webserver ограничение «No TLS, auth, or origin policy» сужено до «No TLS or origin policy; token — единственный контроль доступа». Потеряно/осознанно не сделано: токен печатается в консоль (виден любому с доступом к терминалу — приемлемо для dev-инструмента); cookie без `Secure`, потому что поверхность — HTTP; TLS нет, поэтому секрет ходит по LAN в открытом виде; ротация и отзыв — только рестарт с новым значением; `DSH_WEB_URL` без токена означает, что модель сама GUI не откроет при включённом гейте.

## Testing

- `packages/host/webserver/tests/webserver.spec.ts` — реальная композиция через Loader: отказ без учётных данных (маршрут, fallback, upgrade), обмен `?token=` на cookie, допуск cookie/Bearer/query, отказ неверных значений во всех каналах (включая `Bearer `, `Basic`, битую пару cookie), допуск upgrade по cookie и query, валидация пустого токена.
- `packages/bundle/web-app/tests/startup.spec.ts` — публикация `--token`, пустое значение, help; `tests/web-app.spec.ts` — суффикс `?token=` в обоих URL строки готовности и отсутствие токена в prompt-секции.
