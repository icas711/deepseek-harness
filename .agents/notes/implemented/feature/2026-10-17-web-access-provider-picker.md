# Agent Note: Выбор провайдеров веб-доступа в настройках веб-GUI

Status: implemented

## Problem

Шов веб-доступа [`dsh-web`](../../implemented/architecture/2026-06-24-web-capability-seam.md) поддерживает несколько поисковых провайдеров (DeepSeek, Z.ai, Exa, Perplexity) и один fetch-провайдер (`web-fetch-http`), но для пользователя веб-GUI всё это невидимо и недоступно:

- выбор провайдера задаётся только в cordis.yml (`searchProvider`) или окружением (`$DSH_WEB_SEARCH_PROVIDER`), а `WebRuntime` фиксирует идентификатор в конструкторе — сменить его в работающем деплое нельзя;
- в разделе настроек «Плагины» есть карточка только у DeepSeek ([паттерн settings-секций](../../implemented/feature/2026-08-10-web-plugin-configuration.md)); Exa, Perplexity и Z.ai не регистрируют settings-namespace, их параметры живут только в композиции;
- пользователь не может ни увидеть, какие провайдеры существуют, ни выбрать один из них, ни настроить его из браузера;
- fetch в поставке выключен (`tool-web` собран с `fetch: false`, провайдер не смонтирован), потому что `web-fetch-http` не имеет защиты от SSRF — его собственная документация запрещает включать его там, где цель запроса выбирает модель; управляемого пути включения нет.

## Decision

Единая поверхность «Веб-доступ» в «Настройках → Плагины»: списки поисковых и fetch-провайдеров с выбором одного активного, настройки выбранного провайдера раскрываются рядом. Принятые продуктовые решения (подтверждены владельцем продукта 2026-10-17):

1. **Один активный + «Авто»** — семантика выбора шва не меняется: явный идентификатор либо авто-выбор единственного пригодного провайдера; никаких цепочек приоритетов.
2. **Список показывает всех четырёх поисковых провайдеров всегда**; провайдер, не смонтированный в текущем деплое, виден серым с пометкой «плагин не подключён» (факт смонтированности — из данных plugin-inventory).
3. **Полные настройки для всех провайдеров**: на хосте добавляются settings-namespace для Exa, Perplexity, Z.ai и fetch-лимитов `web-fetch-http`; карточка DeepSeek уже существует.
4. **Применение на лету** — `WebRuntime` дорабатывается так, чтобы выбор читался на каждый вызов `search()`/`fetch()`; смена действует со следующего запроса без перезапуска.
5. **Ключи — только через credentials-домен** (как у DeepSeek сейчас): поле в UI пустое, виден статус «задан/не задан», литеральные секреты в settings.yaml не пишутся.
6. **Fetch — тот же паттерн переключателя**: `web-fetch-http` смонтирован в бандл после того, как SSRF-защита реализована и покрыта тестами; `tool-web` включён с `fetch: true`.
7. **Базовый бандл монтирует всех четырёх поисковых провайдеров** — без ключа провайдер инертен: безключевой поиск отвечает `WEB_PROVIDER_CREDENTIAL_MISSING`; композиционный дефолт `searchProvider: zai` сохраняется до явного пользовательского выбора.

### Слои выбора

Новый namespace `web` (владелец — `dsh-web`) хранит `searchProvider`/`fetchProvider` и резолвится по существующей лесенке: схемный дефолт (пусто = «Авто») → композиционная запись → пользовательский слой. Переменные окружения (`$DSH_WEB_*_PROVIDER`) продолжают кормить те же поля как композиционный уровень. Пустое значение на всех слоях = «Авто». «Сброс» в UI удаляет поле пользовательского слоя и возвращает композиционное значение — семантика [`web-plugin-configuration`](../../implemented/feature/2026-08-10-web-plugin-configuration.md) без изменений.

### Реализация по пакетам

**Хост:**

- `packages/web/web` — settings namespace `web` (`installSettingsSection`); `WebRuntime` резолвит выбор на каждый вызов (пользовательский слой → конфиг плагина → env), конструкторской фиксации идентификатора больше нет. Поведение ошибок выбора (`WEB_PROVIDER_CONFIGURED_MISSING`, `_UNAVAILABLE`, `_AMBIGUOUS`) не меняется.
- `packages/web/web-search-zai` — namespace: `apiKeyEnv` (ссылка, дефолт `ZAI_API_KEY`), `baseURL`, `searchEngine`, `count`; ключ резолвится на каждый поиск.
- `packages/web/web-search-exa` — namespace: `apiKeyEnv` (поле-ссылка по образцу Z.ai, fallback `$EXA_API_KEY` сохранён), `baseURL`, `searchType`, `numResults`, `highlightsPerResult`.
- `packages/web/web-search-perplexity` — namespace: `apiKeyEnv` (по образцу), `baseURL`, `model`, `maxTokens`, `searchRecency`.
- `packages/web/web-fetch-http` — SSRF-защита: блокировка private/loopback/link-local/metadata-адресов (RFC 1918, `127.0.0.0/8`, `::1`, `169.254.0.0/16` включая `169.254.169.254`, `fc00::/7`, `0.0.0.0`, multicast) с проверкой после DNS-резолва (защита от DNS rebinding: подключение к проверенному адресу) и повторной проверкой цели каждого same-origin редиректа; плюс namespace лимитов (`maxUrlLength`, `maxResponseBytes`, `maxBodyChars`, `timeoutMs`, `maxRedirects`, `userAgent`) без секретов. Предупреждение «do not enable» снято: защита покрыта тестами.
- `packages/web/web-search-deepseek` — без изменений; совместимость с селектором проверяется тестом.
- `packages/bundle/base/cordis.patch.yml` — строки монтажа `web-search-exa`, `web-search-perplexity`, `web-fetch-http`; `tool-web` включён с `fetch: true`; `searchProvider: zai` остаётся композиционным дефолтом.

**Клиент:**

- `packages/client/ui-settings-plugins` — карточка «Веб-доступ» над namespace `web`: два радиосписка (поиск, fetch) с вариантом «Авто»; несмонтированные провайдеры серым; несмонтированные провайдеры серым по данным plugin-inventory; выбор раскрывает карточку соответствующего провайдера (карточки провайдеров остаются самостоятельными карточками таба по существующей slot-модели, селектор их автораскрыает и подсвечивает). Карточки провайдеров собирает обобщённый `ProviderCardController`, селектор — `WebAccessCardController`: staged-форма, ключ через credentials-домен, override-пометки, reset; частный случай `WebSearchCard`/`web-search-card-controller` удалён. Предупреждения: выбранный провайдер без ключа; «Авто» при нескольких пригодных провайдерах (шов ответит `WEB_PROVIDER_AMBIGUOUS`).
- `packages/client/locale` — новые строки ru-словаря.

### Тестирование

- Юнит-тесты: резолв слоёв выбора, реактивность смены, блокировка приватных адресов (прямые URL, результаты DNS, цели редиректов, IPv6).
- Безключевой snapshot-сценарий через реальный запускаемый пример (политика тестирования); real-API e2e самоскиппается без ключей провайдеров.
- Браузерный e2e-сценарий селектора (`apps/web/tests/web-access-settings.e2e.ts`) реплеится по golden без ключей и без модельных вызовов.
- HMR-тесты disposal для новых регистраций секций и провайдеров; покрытие per-file 100%; doc-sync.

## Consequences

Все четыре поисковых провайдера и fetch-провайдер смонтированы в базовом бандле; смена провайдера действует со следующего вызова без перезапуска, а «сброс» возвращает композиционное значение. Безключевое поведение единое: синхронный `available()` подтверждает только наличие источника ключа, а безключевой поиск у всех четырёх провайдеров отвечает `WEB_PROVIDER_CREDENTIAL_MISSING` (у Z.ai раньше был `WEB_PROVIDER_ERROR`). Композиционный дефолт `zai` гасит случайный резолв ключей Exa и Perplexity из окружения деплоя. `web_fetch` включён в базовом бандле под SSRF-гардом, но Web-поверхность остаётся search-only: её пресеты несут `tool-web` с `fetch: false`. Экспонируемость новых namespace — решение хоста: список `WEB_SETTINGS_NAMESPACES` (`dsh-host-apiproxy`) дополняют при появлении surface.

## Alternatives considered

- **Приоритетный список с fallback.** Требует расширять сам шов: [`web-capability-seam`](../../implemented/architecture/2026-06-24-web-capability-seam.md) явно запрещает скрытые цепочки приоритетов, а ошибки выбора — часть модельного контракта. Проиграло: меняло бы проверенный фундамент ради UI-удобства.
- **Показывать в списке только смонтированных провайдеров.** Консервативнее и точно следует философии таба «что деплой запускает», но пользователь не узнаёт, что альтернативы существуют, и не может осознанно запросить их подключение. Проиграло: обнаруживаемость — половина ценности фичи.
- **Сначала только выбор, настройки остальных провайдеров потом.** Меньше объём первого шага, но выбор без настроек ведёт в тупик: ключ Exa всё равно негде ввести. Проиграло: фича без форм не завершается сценарием «добавил ключ — выбрал — работает».
- **Применение смены после перезапуска.** Не требует трогать `WebRuntime`, но противоречит ожиданиям, заданным страницей Models и [`web-plugin-configuration`](../../implemented/feature/2026-08-10-web-plugin-configuration.md), где изменение настроек действует сразу. Проиграло: несогласованный UX.
- **Литеральные API-ключи в форме настроек.** Проще для локальных деплоев, но секрет попадает в settings.yaml, а Z.ai уже предпочёл `apiKeyEnv` by design. Проиграло: credentials-домен уже решает эту задачу безопасно.
- **Монтировать `web-fetch-http` без SSRF-защиты.** Прямо запрещено документацией провайдера: модель получает инструмент выбора цели запроса без защиты внутренней сети хоста. Отклонено как неприемлемый риск; включение возможно только после защиты.
- **Не монтировать fetch вовсе, ограничиться поиском.** Минимальный скоуп, но паттерн переключателя всё равно строится обобщённо, а отложенный без SSRF-работы fetch так и остался бы мёртвым кодом. Проиграло: решение владельца продукта — довести fetch до включаемого состояния.

## Risks

- **SSRF-защита — самая сложная часть**: DNS rebinding, повторная проверка после редиректов, IPv6-зоны, крайние случаи диапазонов. Недоделанная защита даёт ложное чувство безопасности, поэтому критерий включения fetch в бандл — именно покрытие тестами, а не наличие фильтра.
- **`WEB_PROVIDER_AMBIGUOUS` при «Авто»**: после монтажа всех четырёх провайдеров пользователь, добавивший два ключа и сбросивший выбор в «Авто», получит ошибку исполнения; UI обязан предупреждать об этом заранее.
- **Реактивный выбор меняет контракт `WebRuntime`**: конструкторская фиксация идентификатора сейчас молча полагается тестами и реплеями; переход должен сохранить поведение сценариев, где настройки отсутствуют.
- **Монтаж Exa/Perplexity расширяет поверхность случайного резолва ключей** из окружения деплоя (`EXA_API_KEY` и т.п.): явный композиционный дефолт `zai` это гасит, но поведение «ключ появился — провайдер стал пригодным» стоит задокументировать в README бандла.
- Заметка [`web-default-search`](../../implemented/feature/2026-07-31-web-default-search.md) описывала композицию на момент deepseek-дефолта; её факты обновлены той же сменой (сегодня дефолт — Z.ai в `packages/bundle/base/cordis.patch.yml`, fetch включён). Дефолтный Z.ai-провайдер введён [`web-search-zai-provider`](../../implemented/feature/2026-08-24-web-search-zai-provider.md).
