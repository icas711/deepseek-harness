# Agent Note: Секции рабочих областей сортируются по свежести по умолчанию

Status: implemented

## Problem

Порядок секций рабочих областей в сайдбаре совпадал с долговым порядком реестра Host: раскладка определялась моментом создания областей и ручным перетаскиванием и не зависела от работы. Пользователь с десятками областей каждый раз искал актуальную вручную: только что завершившаяся сессия в дальней области никак не поднимала её секцию. Сортировка «По обновлению» в меню «Параметры просмотра» действовала только на сессии внутри групп.

## Decision

Меню «Параметры просмотра» браузера получает третью группу — «Сортировка областей» («Вручную» / «По обновлению»), с состоянием в том же персистентном сторе просмотра (`ui-workspace`, `stores.ts`) и значением по умолчанию «По обновлению». Режим «По обновлению» — чистая клиентская проекция: чистая функция `orderWorkspacesByRecency` (`tree.ts`) упорядочивает секции по максимуму `updatedAt` их известных сессий — той же связи свежести, что и проекция `recentWorkspaceId` в рантайме, — а секции без известной сессии (пустые, либо сводки ещё не подтянуты) прижимаются вниз по убыванию даты создания. Стабильные сортировки сохраняют порядок Host внутри каждого равенства, так что переключение режима ничего не «перемешивает». «Без группы» остаётся прижатой внизу, как и раньше.

Режим «Вручную» сохраняет прежнее поведение целиком: drag-секция пишет долговую `workspace.insertBefore`. В режиме «По обновлению» drag-аффорданс секций не рендерится, и `commitWorkspaceDrag` дополнительно защищён проверкой режима: автопорядок никогда не пишется в реестр и не создаёт браузерного аккаунта порядка — следующее же изменение активности переупорядочивает секции заново без какой-либо очистки хранилища. Браузерное состояние режима читается через `resolveWorkspaceOrder`, потому что персистентная запись — цельный JSON-блоб, и блобы, записанные до появления поля, его не содержат.

Значение по умолчанию изменено сознательно (запрос пользователя): свежая область сверху без единого действия.

## Alternatives considered

**Заменить ручной порядок полностью.** Отклонено: drag-порядок — долговая и разделяемая между перезагрузками функция; её сохранение в режиме «Вручную» стоит одного пункта меню.

**Сортировать области на Host при каждом изменении сессий.** Отклонено: порядок реестра — долговая сущность с фреймами `host/workspace-order-changed`; активность сессий не должна переписывать её и рассылать порядок всем наблюдателям, включая TUI и ACP.

**Считать пустые области по `createdAt` в общем порядке.** Отклонено: пустая область — навигационный якорь, а не результат работы; закрепление внизу делает подъём секции надёжным сигналом появления сессии.

## Consequences

- Секции по умолчанию движутся при каждой смене активности — в том числе при завершении фоновой сессии. Переключение в «Вручную» возвращает устойчивый порядок.
- Хост-порядок не меняется ни в каком режиме; долговая семантика `workspace.insertBefore` и [порядка сайдбара](2026-08-11-workspace-sidebar-order-and-folding.md) сохраняется, drag остаётся единственным способом её изменить.
- Плоское «Единым списком» не затронуто: у него нет секций областей.

## Тестирование

`packages/client/ui-workspace/tests/tree.client.spec.ts` — юнит `orderWorkspacesByRecency` (свежесть desc, пустые внизу по созданию desc, равенство — порядок Host, входной массив не мутируется) и `resolveWorkspaceOrder` (умолчание «По обновлению»). `workspace-browser.client.spec.tsx` — секции упорядочены по свежести без сохранённого выбора; меню пишет режим в стор; в авторежиме нет drag-аффорданса и `insertWorkspaceBefore` не вызывается; «Вручную» возвращает порядок Host; существующие drag-спецификации закреплены на «Вручную» сидом `beforeEach`.
