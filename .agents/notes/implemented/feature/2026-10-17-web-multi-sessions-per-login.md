# Agent Note: Несколько веб-сессий на один логин в web-auth

Status: implemented

## Problem

Одна сессия на логин (новый вход отзывал предыдущую) выбивала параллельные устройства одного пользователя: вход с телефона гасил сессию браузера и наоборот. Для человека с двумя машинами или несколькими вкладками веб-поверхность DSH делалась непригодной, а замена не давала ничего взамен — защиты от раздачи пароля она не обеспечивала.

## Decision

Плагин `web-auth` (`packages/bundle/web-app/src/webauth.ts`) держит несколько сессий на логин.

Хранилище `web-sessions.json` — формат `version: 2`: каждая запись несёт `lastSeenAt`, время последнего аутентифицированного запроса. Файл версии 1 отклоняется громкой ошибкой `unsupported session store version 1 (the current format is 2)` по политике репозитория: старые форматы на диске отвергаются, миграций нет; удаление файла возвращает всех пользователей на страницу входа.

Лимит — config-поле `maxSessionsPerUser` (`z.natural().min(1).default(5)`), из развёртывания проводится переменной `DSH_WEB_MAX_SESSIONS_PER_USER` в строке `web-auth` `cordis.patch.yml`. Новый вход сверх лимита вытесняет самые давние по `lastSeenAt` сессии этого логина до лимита; при равенстве `lastSeenAt` порядок вытеснения — порядок выпуска (стабильная сортировка).

`lastSeenAt` обновляется при каждом аутентифицированном запросе (в `identityFor`), запись хранилища на диск из этого пути — не чаще раза в `LAST_SEEN_FLUSH_MS = 60_000`: сбой теряет максимум 60 секунд свежести, худшая цена — ошибочное вытеснение сессии, виденной перед сбоем. Входы и выходы сохраняются немедленно.

Выход `/logout` гасит только предъявленную сессию. Смена scrypt-хэша логина (ревизия `rev`) по-прежнему отзывает все его сессии — на загрузке и при каждой проверке; истечение 30 дней не изменилось.

## Alternatives considered

- **Хранить `lastSeenAt` только в памяти.** После рестарта вытеснение деградировало бы до порядка выпуска: сервер «забывал», какое устройство активно. Проиграло: серверная сессия обязана переживать рестарт со всей своей семантикой.
- **Молчаливая миграция версии 1 → 2 (дописать `lastSeenAt = issuedAt`).** Столкнулась с политикой «backends reject old on-disk formats» и правилом «misconfiguration fails loud»: тихая конвертация скрыла бы происхождение данных и умножила бы форматы на диске. Проиграло.
- **Периодический таймер сброса на диск.** Таймер жизненного цикла плагина ради троттлинга одной записи — лишний движущийся узел; троттлинг по факту запроса даёт ту же гарантию «не чаще раза в 60 секунд» без таймера. Проиграло.

## Consequences

Плюс: один логин работает на нескольких устройствах и вкладках; рост числа сессий ограничен лимитом, который развёртывание поднимает осознанно; запись хранилища при обычном трафике не чаще раза в 60 секунд не растёт с частотой запросов.

Минус: после сбоя вытеснение до 60 секунд неточно — активная перед сбоем сессия может быть вытеснена как давняя. Развёртывания с сохранённым файлом версии 1 требуют ручного удаления хранилища и перелогина всех пользователей — цена громкая, но явная.

## Testing

`packages/bundle/web-app/tests/webauth.spec.ts` закрепляет: второй вход сохраняет первую сессию и пишет формат 2 с `lastSeenAt`; вытеснение самой давней по `lastSeenAt` при лимите 2 (порядок недавности расходится с порядком выпуска); `/logout` гасит только свою сессию; смена хэша гасит все сессии логина; файл версии 1 — громкая ошибка.
