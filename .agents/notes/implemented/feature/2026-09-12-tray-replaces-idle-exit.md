# Agent Note: Трей вместо автовыхода — иконка с серверным меню и single-instance гейт

Status: implemented

## Problem

После добавления связи-баннера пользователь переформулировал желаемый жизненный цикл: авто-выход процесса после простоя без браузера (idleExitMs) не нужен вовсе — процесс должен жить, пока его не остановят, а управление должно быть доступно без консоли — из иконки в системном трее. Повторный запуск приложения при живом экземпляре должен открывать уже работающую поверхность в браузере, а не падать с `EADDRINUSE`.

## Decision

Механизм idle-выхода удалён целиком: поле конфига `idleExitMs`, poll `openUpgradeCount` (`web-app/src/idle-exit.ts` удалён) и сам геттер `openUpgradeCount` в webserver (его единственный потребитель был poll). Процесс завершается только явно.

Трей (`web-app/src/tray.ts`, пакет `systray2` с нативным хелпером внутри) — иконка «custom-harness» с меню из трёх пунктов: «Запустить»/«Остановить» управляют веб-сервером через новые `webServer.start()`/`stop()`, «Выйти» вызывает `appExit(0)`. Остановка закрывает слушатель и все соединения, но сохраняет сервис, маршруты и регистрации; `start()` перепривязывается на порт первого бинда (даже при `port: 0` в конфиге), поэтому печатаемый URL и `DSH_WEB_URL` остаются верными, а браузер видит остановку как потерю связи — баннер «Процесс не запущен» показывает состояние без дополнительных механизмов. Отказ запуска хелпера (headless, отсутствие бинарника) деградирует до записи в логе: трей — удобство, не boot-зависимость. Состояние меню («Запустить» enabled при остановленном сервере, «Остановить» — при работающем) рисуется из одного чистого `trayMenu(running)`; клики матчатся по стабильным заголовкам.

Single-instance гейт живёт в `web-startup` (`probeExistingInstance`) и задерживает публикацию `webStartup` — строка webserver инжектит этот сервис, поэтому бинд ждёт вердикта. Проба читает `GET http://127.0.0.1:<порт>/`: маркер `__DSH_BOOT__` в теле (инъекция, которую делает только `dsh web`) или точное 401-тело токен-гейта (`unauthorized`) означают живой экземпляр — тогда запуск печатает `already running at <url>`, открывает браузер (`cmd start`/`open`/`xdg-open`, detached) и выходит через `appExit(0)`. Иной ответ или отказ транспорта публикует сервис: свободный порт биндится, занятый посторонним — отказывает громко, как прежде.

## Alternatives considered

- Скрытый PowerShell-хелпер с NotifyIcon (WinForms) — отклонено: Windows-only, ребёнок powershell.exe с заметным потреблением памяти и стартовой задержкой против поставляемого в пакете бинарника.
- Управление жизнью всего процесса из «Остановить» — отклонено (выбор пользователя): мёртвый процесс не держит ни иконки, ни «Запустить», а баннер в браузере останется без средства восстановления из трея.
- PID/lock-файл для single-instance — отклонено: маркер-проба порта не оставляет файлов на диске и не требует протокола зачистки устаревших локов; токен не пишется никуда.
- Ярлычный уровень (`dsh-web.ps1` уже проверял порт 3080) как единственное место гейта — отклонено: скрипт покрывает только установленный сценарий с фиксированным портом; гейт в провайдере защищает и CLI-запуски с любым `--port`.
- EADDRINUSE-диагностика вместо гейта — отклонено: падение бута не открывает браузер и не отличает свой экземпляр от чужого.

## Consequences

Закрытие браузера больше ничего не завершает: процесс живёт до «Выйти» в трее (или внешнего `dsh-stop.ps1`/сигнала). Остановка сервера из трея делает веб-поверхность недоступной до «Запустить»; перепривязка может отклониться, если порт заняли за время останова — иконка остаётся в остановленном состоянии, пользователь повторяет запуск. Установщик получает `systray2` через обычный heal зависимостей профиля (бинарник внутри пакета). Тестовые линии обязаны выключать трей явно: спеки web-app передают `tray: false`, web e2e scaffold пиннит его в конфиге `web-runtime`, иначе каждая прогонка порождает нативную иконку. Идея-заменитель для иконки не нужна: `scripts/gen-tray-icon.mjs` детерминированно перегенерирует константу `src/tray-icon.ts` (64×64 PNG-in-ICO, знак «пузырь чата»). Связь-баннер из [2026-09-12-connection-loss-chat-banner](2026-09-12-connection-loss-chat-banner.md) остаётся единственным клиентским индикатором — он теперь отображает и остановку сервера из трея.
