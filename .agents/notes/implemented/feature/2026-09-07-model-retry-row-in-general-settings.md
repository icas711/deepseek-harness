# Agent Note: Пять повторов по умолчанию и строка повторов в «Общих» настройках

Status: implemented

## Problem

Два пользовательских запроса об одном механизме. Во-первых, умолчальная политика повторов `dsh-llm` допускала два повтора после первой попытки; при долгом молчании провайдера и транспортных сбоях сессия падала слишком рано, и поднять бюджет без правки `settings.yaml` было нельзя. Во-вторых, у политики не было интерфейса: `retryPolicy` — поле конфигурации провайдера, до сих пор доступное только прямым редактированием YAML, хотя хост уже давно применяет её на лету (адаптер `llm-deepseek` перерегистрирует маршрут на месте при смене политики).

## Decision

**Умолчание.** `DEFAULT_MAX_RETRIES` в `packages/llm/llm/src/retry-policy.ts` увеличено с 2 до 5. Нарастание паузы уже было экспоненциальным и остаётся прежним: 0,5 с с удвоением, потолок 10 с, симметричный джиттер 10%. Бюджет зависит от провайдера и по-прежнему перекрывается конфигурацией; изменился только слот по умолчанию.

**Интерфейс.** Плагин `ui-settings-models` добавляет в раздел «Общие» строку «Повторы при ошибках модели» (`settings.general.item`, id `llm-retries`): число повторов, начальная и максимальная пауза. Чтение — через привязанное зеркало секции `llm-deepseek` (`ctx.settingsScope.bind`, автобновление по `settings/document-updated`); запись — одна операция `settings.mutate` пользовательского слоя с ожидаемой ревизией: сабтри `retryPolicy` замещается целиком с переносом собственных полей пользовательского слоя, поэтому параллельная правка отвечает `settings-conflict`, а не затирается вслепую. «Сбросить» снимает перекрытие одним `unset`, возвращая уровень композиции и затем умолчания схемы. Поля блокируются при режиме `always` (строка его не пишет — это выбор конфигурации), при недоступной секции и при документе «только чтение». Чекбокс «применяется сразу» не нужен по умолчанию: смена политики перерегистрирует маршрут на месте и действует со следующего запроса — это уже существующее свойство хоста, которое интерфейс просто делает видимым.

Строка намеренно адресует единственный роут `deepseek-official` и подписана как параметр DeepSeek: политика принадлежит провайдеру ([роли capability-шва](../../../../docs/glossary.md)), а не глобальному «поведению агента».

## Alternatives considered

**Глобальная секция «повторы» для всех провайдеров.** Отклонено: политикаcapture'ится при регистрации маршрута её адаптером; общий слот либо дублировал бы её в каждый профиль, либо врал про покрытие.

**Писать только `maxRetries` глубинными операциями пути.** Отклонено: `SettingsScope.set` пишет поле верхнего уровня; три глубинных операции на сохранение против одной записи сабтри — первый вариант сложнее и даёт тот же результат слияния слоёв.

**Оставить дефолт 2 и только дать интерфейс.** Отклонено пользователем: запрос — «пять попыток» из коробки; умолчание и есть продукт.

## Consequences

- Худший случай на один шаг вырос: пять пауз вместо двух (в сумме до ~15,5 с локального бэкоффа против 1,5 с) плюс сами попытки. Всегда можно сузить настройкой или режимом `always` для неограниченного повтора.
- Пользовательский слой секции получает полный объект `retryPolicy` после первого сохранения; последующие правки `cordis.yml` по этим трём полям перекрываются, пока пользователь не нажмёт «Сбросить».
- Дефолт поменял наблюдаемые события `llm/retry` (`maxRetries: 5` в фикстурах и e2e) — это и было целью.

## Тестирование

`packages/llm/llm/tests/retry-policy.spec.ts` и `service.spec.ts` закрепляют новое умолчание; `llm-pi-ai/tests/adapter.spec.ts` и `test-support/llm-replay` — профиль без политики. `ui-settings-models/tests/retry-row.client.spec.tsx` — значения из секции, сохранение разобранного черновика, ошибка записи, локальная валидация, блокировки (`always`, read-only, недоступная секция), сброс, сброс черновика по новой ревизии; `apply.client.spec.ts` — регистрация строки и сервис `settingsScope` в `inject`. Реальная композиция — golden'ы окна настроек в `apps/web/tests` (`DSH_SNAPSHOT`).
