# Agent Note: Веб-панель администрирования — хранилище пользователей и домен admin.*

Status: implemented

## Проблема

Вход по паролю в веб-поверхности держал пользователей в окружении (`DSH_WEB_USERS`/`DSH_WEB_ADMINS`): смена пароля, отключение устройства или создание аккаунта требовали правок окружения и перезапуска, а «устройство» пользователя (второй браузер, телефон) нельзя было отключить дистанционно. Одновременно сервис `webAuth` уже отдавал шлюзу личность по cookie, и шлюз ограничивал видимость кабинетов, но управления аккаунтами не существовало: интерфейс видел только кнопку «Выйти».

## Решение

Плагин `web-auth` — единоличный владелец управляемого хранилища пользователей `dshHomePath('web-users.json')`: записи `{login, scryptHash, role: 'admin'|'user', createdAt}`, версия формата 1, атомарная запись (`dsh-atomic-write`, режим 0o600), чужой или битый формат — громкий отказ на старте, никакой тихой пересечки. Окружение остаётся сеансом первичной инициализации и восстановления доступа: пустой или отсутствующий файл засевается из `DSH_WEB_USERS`/`DSH_WEB_ADMINS` (роль `admin` — логинам из `DSH_WEB_ADMINS`); хранилище с пользователями окружение полностью игнорирует. Пустой файл вместе с пустым окружением — прежний пассивный режим.

Сервис `webAuth` расширяется лицом администрирования (`WebAuthService` в [`src/web-identity.ts`](../../../../packages/host/apiproxy/src/web-identity.ts)): `listUsers`, `createUser` (хост считает scrypt-хэш), `deleteUser`, `resetPassword` (новый хэш и отзыв всех сессий логина), `setRole`, `listDevices`, `revokeDevice`, `revokeAllDevices`; отказы — типизированный `WebAdminError`. Роль хранится в записи и перечитывается на каждом запросе, поэтому смена роли действует мгновенно и без отзыва сессий; последний админ защищён от удаления и понижения — иначе деплой терял бы возможность управлять собой, а восстановление через окружение работает только на пустом хранилище.

Шлюз раздаёт это лицо доменом `admin.*` (`admin.status` доступен любому аутентифицированному, остальные — только роли `admin`; все гейтятся одной точкой `requireAdmin` через `requestIdentity`): без веб-личности (TUI/headless, пассивный деплой) или у не-админа — типизированный `admin-forbidden`; коды сервиса маппятся в `admin-user-not-found`/`admin-user-exists`/`admin-device-not-found`/`admin-last-admin`/`admin-rejected`. «Устройство» — те же серверные сессии v2: отзыв мгновенно персистит `web-sessions.json`, а смена хэша при сбросе дополнительно гасит все сессии логина механикой ревизии.

В браузере секция «Администрирование» (`dsh-client-ui-admin`, слот `settings.section`) ставится только когда `admin.status` ответил утвердительно; перелогин перепроверяет. Клиентская проверка — удобство сокрытия: подлинный гейт на хосте в каждом методе. Сброс пароля генерирует новый пароль на клиенте (хост хранит только хэш) и показывает его один раз — «показать снова» не существует по построению.

## Альтернативы

- **Оставить окружение источником истины, добавить RPC над env.** Отклонено: env неизменяем в живом процессе, запись всё равно требует файла; два источника порождают вопрос «кто выигрывает» на каждом старте. Сеанс-первичный засев делает ответ однозначным: файл, окружение — только семя и лома-отмычка.
- **Генерировать новый пароль на хосте и возвращать его в ответе `resetPassword`.** Отклонено: контракт метода становится «пароль в ответе», и случайное логирование RPC-конвертов (envelope-наблюдатель носителя) получает пароль; клиентская генерация оставляет на хосте только хэш.
- **Скрыть страницу только на клиенте, роль проверять на сервисе `webAuth`.** Отклонено как единственная линия: сервис доступен любому in-process плагину, а гейт принадлежит границе вызова — одна точка `requireAdmin` в шлюзе закрывает все методы домена и даёт обычному пользователю типизированный отказ, а не пустой результат.
- **Разрешить удалять/понижать последнего админа с восстановлением через env.** Отклонено: восстановление работает только на пустом хранилище, значит «удалил единственного админа» без отдельной ручной правки файла — безвыходное состояние; явный отказ `admin-last-admin` дешевле аварийного плана.

## Последствия

Панель закрывает повседневные операции без доступа к окружению, но уровень модели угроз не меняется: агенты всех пользователей исполняются в одном контейнере, и «удалить пользователя» — это запись в файл, а не изоляция. Сессии, созданные до включения входа, по-прежнему видимы только админам; устройство-отзыв не «разлогинивает» прочитанные данные, а лишь закрывает доступ дальше.

Формат хранилища версионируется с первого дня (`version: 1`, громкий отказ на чужую версию) — как у `web-sessions.json` v2; миграции появятся вместе со вторым форматом. `DSH_WEB_USERS`/`DSH_WEB_ADMINS` сохранены: без них не работает первый старт и восстановление доступа, но теперь это документы о засеве, а не реестр.
